# GenoLigand 后续实施方案

本文只围绕三件事写：界面、科学结果可追溯、安装与数据库闭环。后续编码按本文执行，不再拆成互不相干的小目标。

## 一、界面

目标：普通科研用户安装后第一次打开，看到干净空白工作台，直接输入研究对象，按 `Input（输入）-> Configure（配置）-> Check（检查）-> Run（运行）-> Results（结果）-> Export（导出）` 完成一次运行。

当前已完成：

1. WebUI（网页界面）主流程已压缩为输入、配置、检查、运行、结果、导出。
2. 首次打开不创建示例项目、不显示测试 run、不显示预置结果。
3. 普通主界面不显示 GitHub（代码托管平台）、提交号、远端仓库、结构约束文件、来源清单、完整性标识、JSON（结构化数据文本）、验证门、路由等开发者概念。
4. 五类输入已经进入同一个入口：小分子、多肽、蛋白质配体、复合物结构、自定义基因组/宏基因组。
5. 运行中心页已经显示流程阶段、当前状态、下一步动作、资源计划、恢复建议、可导出结果和折叠运行事件。
6. 结果页已经按候选排序、候选详情、证据链、Genome/ORF（基因组/开放阅读框）、Structure/Patch（结构/结合区域）、MD Summary（分子动力学摘要）分区。

后续实现步骤：

1. 统一所有页面的暗色配色、表格密度、按钮层级、空状态、错误状态和加载状态。
2. 将长表、长日志、长证据链统一成可滚动区域，默认折叠底层日志。
3. Structure/Patch 页面接入三维结构查看器；接入前只显示未就绪状态和已有表格摘要。
4. MD Summary 页面接入 RMSD、RMSF、接触、氢键、配体漂移和分数拆解图；接入前只显示未就绪状态和已有摘要表。
5. Settings 和 Diagnostics 只显示普通用户可执行动作；高级维护入口默认隐藏。

验收标准：

1. 首次打开项目列表为空，结果为空，候选为空。
2. 用户不需要理解开发者概念即可完成输入、检查、运行、查看结果和导出。
3. 主界面没有测试痕迹、乱码、杂乱入口、长解释句和开发者字段。
4. Run Monitor 是运行中心页。
5. 结果页在没有当前运行产物时保持为空，不展示占位候选。

## 二、科学结果可追溯

目标：WebUI 中出现的候选、分数、结构、动力学图、证据链、报告和诊断状态，都来自用户输入、科学仓库、后端运行和当前 run 产物。没有来源的内容不显示。

当前已完成：

1. 无输入时不生成候选。
2. 科学仓库缺失时运行被阻塞，候选数为 `0`。
3. 结果接口只读取当前 run 的输出文件。
4. header-only 输出文件不算用户结果。
5. 报告下载只允许当前 run 的白名单产物。
6. 结构和动力学图形化未接入时显示未就绪状态，不使用预置曲线或预置结构。

后续实现步骤：

1. 完成五类输入的统一归一化产物 `input_normalized_manifest.tsv`。
2. 完成五类输入的特征计算产物 `feature_manifest.tsv`。
3. 从特征出发生成已知数据库命中 `known_database_matches.tsv`。
4. 从特征出发生成宏基因组潜在序列命中 `metagenome_potential_matches.tsv`。
5. 生成结构、口袋、界面、对接和短分子动力学摘要表。
6. 由 Rust（系统核心语言）核心合并候选排序、分数拆解、证据链和报告语义。
7. Python worker（科学计算工作进程）只执行结构化计算任务，不写最终排序、最终分数或报告解释。
8. 第三方工具输出必须转换为 GenoLigand 自有表格和 JSON 结构，不直接进入用户报告。

验收标准：

1. 每个候选都能追溯到 project、run、input、database、candidate ID 和 artifact。
2. 没有当前 run 产物时，候选排序、候选详情、证据链、结构摘要、动力学摘要和导出页均为空。
3. 不能执行的功能明确显示未就绪。
4. 报告只写候选假设、优先级、证据和建议实验验证。
5. 任何无来源候选、无来源分数、预置结构、预置动力学曲线或固定结果表数量为 `0`。

## 三、安装与数据库闭环

目标：用户用一条命令安装并启动，安装流程自动准备计算环境、数据库、索引、来源记录、完整性记录和许可记录。普通用户不手动配置数据库路径。

当前已完成：

1. 安装入口 `install_complete_scientific.py` 可准备科学仓库、Python 科学计算环境、来源记录、完整性记录和许可记录。
2. `gls-server`（本地后端服务）已经提供安装状态、安装计划和安装/修复接口。
3. 科学仓库就绪条件已经包含数据库索引、工具版本、安装状态、科学资源状态、来源记录、完整性记录和许可记录。
4. WebUI 检查页已显示安装/修复状态、数据库资源状态、大型资源状态、来源与许可记录、计算环境状态和缺失项。
5. 数据库下载安装/修复过程已写入 `install_progress.json`，后端通过 `/api/user/setup/progress` 提供阶段、当前资源、步数、下载量和百分比。
6. WebUI 安装/修复按钮已接入进度条，运行期间每秒刷新一次。

后续实现步骤：

1. 补齐发行安装脚本，覆盖 Windows/WSL2 和 Linux。
2. 安装时自动检测 Java、Nextflow、Python worker、OpenMM、RDKit、MDTraj、MDAnalysis、PDBFixer、CUDA/OpenMM 后端、gls-cli、gls-server 和数据库索引工具。
3. 数据库下载支持断点续传、校验、失败重试、来源记录和许可记录。
4. 数据库下载安装界面必须显示可视化进度条，包含阶段、资源名、完成步数、下载量、百分比和失败数。
5. 安装完成后自动运行科学仓库检查；未闭合时 Diagnostics 给出可执行修复动作。
6. 测试结束后清理测试项目、测试 run、缓存、临时 artifact、截图和日志。

验收标准：

1. 新机器执行安装命令后能启动 WebUI。
2. 科学仓库就绪后 `science_store_manifest.tsv`、`install_status.json`、`source_requirements.tsv`、三个数据库索引、工具版本记录、来源记录、完整性记录和许可记录都存在并通过检查。
3. 安装或数据库缺项时主流程阻塞，候选数为 `0`，并给出可执行修复动作。
4. 数据库下载或同步期间 WebUI 显示进度条。
5. 安装完成后打开的是干净空白工作台。
6. 测试不会污染最终交付状态。

## 最终验收报告格式

最终验收只写三部分：

1. 界面是否像正式软件。
2. 科学结果是否可追溯。
3. 安装和数据库是否能从零跑通。

三部分全部通过，才算本轮目标完成。
